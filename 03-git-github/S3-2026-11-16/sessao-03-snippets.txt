ANTES DE COMEÇAR · SLIDE 4 (PRÓPRIA 2)

Quem sou eu no Git? O email tem de ser o da vossa conta do GitHub (é assim que os commits aparecem com a vossa cara):

    git config --global user.name
    git config --global user.email

Não é o da conta? Mudem-no:

    git config --global user.email "o.email@da.conta"

Têm duas contas no GitHub (a pessoal e a do trabalho)? Não mexam no --global (fica a do trabalho). Digam ao Git para usar a conta pessoal só dentro da pasta do curso (uma vez por computador):

    git config --global includeIf."gitdir:~/Documents/flag-frontend/".path ~/.gitconfig-flag
    git config --file ~/.gitconfig-flag user.name "O Vosso Nome"
    git config --file ~/.gitconfig-flag user.email "o.email@da.conta.pessoal"

- Windows: gitdir/i: em vez de gitdir:. O caminho é o da vossa flag-frontend e acaba em /.
- Para confirmar, dentro de um repositório do curso (o livro, por exemplo): git config --show-origin user.email mostra o .gitconfig-flag e o email pessoal. Fora de um repositório aparece o global: é normal.
- No browser, antes do Authorize do primeiro push, confirmem a conta no canto superior direito do GitHub.
- Tudo explicado: 03-git-github/recursos/duas-contas-github.md (no repositório do curso).

- Ainda não têm conta? github.com › Sign up, com esse mesmo email. O GitHub pede 2FA: uma app de autenticação no telemóvel. Guardem os recovery codes.
- No chat: o vosso username do GitHub (é para vos convidar para o repositório da turma).

PARTE 1 · O GITHUB

› [TEORIA] O local e o remoto · slide 6 (própria 4)

  → Só para consulta: não é para escrever agora. Escrevemos juntos no slide 8.

- O Git é o programa: guarda as versões no vosso computador. O GitHub é um serviço: guarda uma cópia do repositório na nuvem, com uma página web, a equipa e as revisões.
- O repositório do GitHub é o remoto; o vosso é o local. O histórico é o mesmo: os commits viajam de um para o outro.

› [TEORIA] Os quatro verbos · slide 7 (própria 5)

  → Só para consulta: não é para escrever agora. Escrevemos juntos no slide 8.

    git clone <endereço>    # a primeira vez: copia o repositório todo (e fica ligado ao remoto, o origin)
    git push                # envia os meus commits
    git fetch               # traz os commits novos, sem mexer nos meus ficheiros
    git pull                # traz e junta (fetch + merge)

⚠️ Pull quando começo, push quando acabo.

› [STOP · ESCREVER JUNTOS] O clone do curso, juntos · slide 8 (própria 6)

  → Agora escrevemos todos, passo a passo, no terminal do VS Code. Eu partilho o ecrã.

PARTE 2 · O LIVRO NO GITHUB

› [TEORIA] A autenticação · slide 11 (própria 9)

  → Só para consulta: não é para escrever agora. Hoje a autenticação acontece sozinha no slide 15, no terminal do VS Code.

- A password da conta não serve no terminal (desde 2021).
- Hoje, no VS Code: no primeiro git push, o VS Code pergunta "The extension 'GitHub' wants to sign in" › Allow › o browser abre › Authorize Visual Studio Code. Fica guardado.
- Fora do VS Code, no Windows: o Git Credential Manager (vem com o Git) abre o browser do mesmo modo.
- Plano B, no Mac (ou se o VS Code não pedir): a GitHub CLI.

    brew install gh                     # Mac (no Windows: winget install GitHub.cli)
    gh auth login                       # GitHub.com › HTTPS › Yes › Login with a web browser
    gh auth status

- Mais tarde: SSH. Uma chave no computador e a outra no GitHub:

    ssh-keygen -t ed25519 -C "o.email@da.conta"   # Enter, Enter, Enter
    cat ~/.ssh/id_ed25519.pub                     # copiar para GitHub › Settings › SSH and GPG keys › New SSH key
    ssh -T git@github.com                         # Hi <username>! You've successfully authenticated…

(Com SSH, os endereços passam a ser git@github.com:<username>/livro.git. Os passos todos: o Extra · SSH, no fim destes snippets, e o tutorial 03-git-github/recursos/tutorial-ssh-github.md.)

› [TEORIA] Criar o repositório · slide 12 (própria 10)

  → Só para consulta: não é para escrever agora. Criamos o do livro juntos no slide 15.

- No GitHub: o + no canto superior direito › New repository › o nome (curto, minúsculas, hífenes).
- Public: todos veem e clonam; só escreve quem vocês deixarem. Private: só vocês e quem convidarem.
- ⚠️ Já têm histórico? Criem-no vazio: sem README, sem .gitignore, sem licença. Senão o push é recusado.
- Muda-se depois: Settings › General › Danger Zone › Change visibility.

› [TEORIA] remote e push · slide 13 (própria 11)

  → Só para consulta: não é para escrever agora. Escrevemos juntos no slide 15.

    git remote add origin https://github.com/<username>/livro.git   # dar nome e endereço ao remoto
    git remote -v                                                   # para onde aponta
    git push -u origin main                                         # a primeira vez (o -u liga o main ao origin/main)
    git push                                                        # daí em diante

› [TEORIA] O histórico no GitHub e o GitHub Pages · slide 14 (própria 12)

  → Só para consulta. O histórico vemos juntos no slide 15; o Pages fazem vocês no 5.1.

- Commits (o relógio por cima dos ficheiros): a lista. Um clique num commit: o que mudou (verde entrou, vermelho saiu).
- Num ficheiro: History (só os commits dele) e Blame (quem mudou cada linha).
- Insights › Network: o desenho dos branches, como o --graph.
- GitHub Pages: Settings › Pages › Build and deployment › Deploy from a branch › main / (root) › Save. O site fica em https://<username>.github.io/<repositório>/.

› [STOP · ESCREVER JUNTOS] O livro no GitHub, juntos · slide 15 (própria 13)

  → Agora escrevemos todos, passo a passo, no livro. Eu partilho o ecrã.

1 · No GitHub: + › New repository › livro › Public › sem README › Create repository. Copiar o endereço HTTPS.

    # 2 · no terminal do VS Code, na pasta do livro (a da 6.ª)
    cd …/livro
    git status                          # nothing to commit, working tree clean
    git log --oneline --graph --all
    
    # 3 · ligar ao GitHub
    git remote add origin https://github.com/<username>/livro.git
    git remote -v
    
    # 4 · enviar (a primeira vez, o VS Code pede para entrar: Allow › Authorize)
    git push -u origin main

5 · Atualizar a página do repositório: os ficheiros, o número de commits, um commit aberto (o Revert!), o History do livro.txt, Insights › Network.

    # 6 · uma mudança, e enviar (já sem o -u)
    # … mudar uma frase no livro.txt …
    git commit -am "Muda o prefácio"
    git push

- Não têm o livro? O livro-s03.zip está no clone do curso (flag-frontend-2026/03-git-github/s03): copiem-no para a flag-frontend/03-git-github/s03/ e descompactem-no lá.
- Permission to <username>/livro.git denied to <outra-conta> (403): o computador guardou a credencial da outra conta (a do trabalho). Ponham o username no endereço e voltem a enviar (pede a conta certa): git remote set-url origin https://<username>@github.com/<username>/livro.git e git push -u origin main.
- Support for password authentication was removed: estão num terminal fora do VS Code. Usem o do VS Code (ou o plano B, gh auth login).
- ! [rejected] main -> main (fetch first): criaram o repositório com README. Apaguem-no (Settings › Danger Zone) e criem-no vazio.
- error: remote origin already exists: git remote -v; se estiver errado, git remote set-url origin <endereço certo>.

PARTE 3 · EM EQUIPA

› [TEORIA] Pull e fetch · slide 20 (própria 18)

  → Só para consulta: não é para escrever agora. O pull fazemos juntos no fim do slide 24.

    git pull                            # no início: trazer o que os outros fizeram (fetch + merge)
    git push                            # no fim: enviar o que eu fiz
    
    # o aviso de um dia destes:
    #  ! [rejected]  main -> main (fetch first)
    git pull                            # primeiro trazer (se houver conflito, resolve-se como na 6.ª)
    git push                            # depois enviar

› [TEORIA] Colaboradores e equipas · slide 21 (própria 19)

  → Só para consulta.

- Num repositório pessoal: Settings › Collaborators › Add people. O convidado aceita (email ou github.com/notifications) e passa a poder escrever.
- Numa organização: as pessoas entram em equipas, e cada equipa tem uma permissão por repositório: Read (ver e clonar) · Triage (+ gerir Issues) · Write (+ push) · Maintain (+ configurações) · Admin (tudo).

› [TEORIA] Pull Requests · slide 22 (própria 20)

  → Só para consulta: não é para escrever agora. Fazemos um juntos no slide 24.

O fluxo: branch → commits → push → Pull Request → revisão → merge (e depois, todos fazem pull).

- A revisão: no separador Files changed, comentários linha a linha. No fim: Comment, Approve ou Request changes.
- Os checks: o GitHub Actions pode correr testes a cada push (✓ ou ✗).
- As regras do main (branch protection): ninguém faz push direto; só com PR aprovado.
- Num projeto onde não têm permissão de escrita: Fork (uma cópia na vossa conta) e o PR de lá.

› [TEORIA] Issues e Projects · slide 23 (própria 21)

  → Só para consulta: vão usá-las no exercício 5.2.

- Issues: uma tarefa ou um erro, com número (#1), labels e a quem está atribuída.
- Closes #1 na descrição de um PR: quando o PR é juntado ao main, a Issue fecha-se sozinha.
- Projects: um quadro (Todo › In Progress › Done) com as Issues da equipa.

📖 TEORIA · HTTPS OU SSH? · SLIDE 31 (PRÓPRIA 29)

  HTTPS (o que usámos)  ·  SSH
  O endereço  ·  https://github.com/<username>/livro.git  ·  git@github.com:<username>/livro.git
  Como entra  ·  o browser autoriza; o computador guarda  ·  um par de chaves: a privada no computador, a pública no GitHub
  Configurar  ·  nada  ·  uma vez por computador

A chave privada (id_ed25519) nunca sai do computador. A pública (id_ed25519.pub) vai para o GitHub.

✍️ STOP · MOSTRO EU · CONFIGURAR O SSH · SLIDE 32 (PRÓPRIA 30)

> Mostro eu (num repositório meu: já tenho chave). Vocês fazem em casa, com o tutorial. Windows: tudo no Git Bash.

    ls -al ~/.ssh                                    # já há chaves? (id_ed25519 e id_ed25519.pub)
    ssh-keygen -t ed25519 -C "o.vosso@email.pt"      # Enter (o sítio) e uma passphrase (2 vezes)

    # copiar a PÚBLICA (o .pub!)
    pbcopy < ~/.ssh/id_ed25519.pub                   # Mac
    clip < ~/.ssh/id_ed25519.pub                     # Windows (Git Bash)

    # GitHub › Settings › SSH and GPG keys › New SSH key › colar › Add SSH key

    ssh -T git@github.com                            # à primeira pergunta: yes
    # Hi <username>! You've successfully authenticated, but GitHub does not provide shell access.

    git remote -v                                    # https://github.com/…
    git remote set-url origin git@github.com:<username>/livro.git
    git remote -v                                    # git@github.com:…
    git push                                         # já não abre o browser

Para não escrever a passphrase sempre (o ssh-agent):

    # Mac: no ficheiro ~/.ssh/config
    #   Host github.com
    #     AddKeysToAgent yes
    #     UseKeychain yes
    #     IdentityFile ~/.ssh/id_ed25519
    eval "$(ssh-agent -s)"
    ssh-add --apple-use-keychain ~/.ssh/id_ed25519   # Mac
    ssh-add ~/.ssh/id_ed25519                        # Windows (Git Bash)

Clonar com SSH: no GitHub, Code › SSH › copiar: git clone git@github.com:<username>/receitas.git.
